# Design

## Context

- 动机和范围见 proposal.md，行为要求见 `specs/` 下四份规格。
- 游戏是 Go + tcell 的终端程序。关卡格式由 `pkg/level` 定义：15 行字符网格，加上 `contents`、`entities`、`spawn`、`flag`。解析器 `Parse` 开着 `DisallowUnknownFields`，每条拒绝都带行列号。
- **关键事实（已验证）**：`pkg/game` 和 `pkg/render` 能用 `GOOS=js GOARCH=wasm` 编过。`render.Scene.Draw(world)` 输出的是"艺术像素"缓冲 `Canvas`，颜色是 `tcell.Color` 令牌，本质上是 24 位 RGB（`theme.hex`）。所以浏览器里可以跑**游戏本体**的模拟和绘制，只是最后一步从"转成终端字符"换成"写进 `<canvas>` 的 ImageData"。
- `pkg/save.Entry` 已经有 `Level` 字段，按关卡记分不用迁移数据。
- 内置关卡现在有两份：`levels/1-1.json` 和 `pkg/level/data/1-1.json`，靠 `make gen-level` 手工拷贝同步。
- 仓库里的 `preview/*.html` 都是零依赖的单文件网页，前端风格可以沿用。

## Goals / Non-Goals

**Goals:**
- 设计器画面、试玩手感、加载校验三者都来自同一份 Go 代码，从结构上杜绝"编辑器里能玩、游戏里不行"。
- 贡献者只要有这个仓库的二进制和一个浏览器，不用装 Node 或 Python，也不用跑前端构建。
- 关卡文件的 diff 对评审友好：排版稳定，一行就是一行地形。

**Non-Goals:**
- 不做通用的 Tiled 式编辑器，也不支持图层或自定义素材。
- 不追求移动端可用。设计器面向桌面浏览器加鼠标；手机能打开，但不保证能编辑。
- 不做跨浏览器的像素级一致，只保证最近两个大版本的 Chrome、Edge、Firefox。

## Decisions

### 1. 形态：同一个二进制里的 `edit` 子命令，加本地 HTTP 服务

`super-mario edit [关卡]` 在 `127.0.0.1` 的随机空闲端口起服务（`--port` 可以指定），用系统默认浏览器打开，并在终端打印地址。前端资源和 WASM 用 `go:embed` 打进二进制。

- **为什么不直接给一个 HTML 文件**：纯静态页面没法写进仓库目录，只能走浏览器下载，用户还得手动挪文件、改名，"好用"就打了折扣。另外 `file://` 下浏览器会限制 WASM 的加载。
- **为什么不单独做一个编辑器二进制**：多一个产物就多一个"版本对不上"的机会。编辑器和游戏同版本，校验规则就同版本。
- **安全**：只绑回环地址；接口只接受同源请求，校验 `Host` 和 `Origin`，防 DNS rebinding；写文件只能写进关卡目录，文件名先按标识规则校验，杜绝路径穿越。

接口很小：

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/api/levels` | 列出内置关卡和元信息 |
| GET | `/api/levels/{id}` | 读一个关卡（原始 JSON） |
| PUT | `/api/levels/{id}` | 保存（服务端再校验一次，写临时文件后 rename） |
| GET | `/` 和静态资源 | 编辑器页面、`editor.wasm`、`wasm_exec.js` |

### 2. 一份 Go 核心编译成 WASM，前端只管交互

新增 `cmd/wasm`，编译出 `editor.wasm`，通过 `syscall/js` 暴露几个函数：

- `validate(json) → {errors, warnings}`：调用 `level.Parse` 和新增的 `level.Lint`。
- `playtest.start(json, opts)` / `playtest.step(inputMask) → frame` / `playtest.stop() → trace`：在 WASM 内部建 `game.World`，每帧 `Step`，再用 `render.Scene.Draw` 出 Canvas，把颜色令牌转成 RGBA 字节交给 JS 贴到 `<canvas>`。
- `sprites() → atlas`：每种元素在编辑器缩放下的位图，由同一套 `render` 素材生成。编辑画布用它贴图，保证"画布与游戏外观一致"。

前端用原生 JS 模块，不用框架，也不引入构建工具：负责画布交互、工具、撤销栈、面板和草稿。

- **为什么不用 JS 重写物理和校验**：两套实现迟早分叉，规格里"试玩与正式游戏一致""单一校验来源"就成了空话。WASM 体积大约 3–5 MB，走本地服务加载可以接受。
- **为什么不在 WASM 里画整个编辑画布**：编辑交互（悬停、预览、选框）每次鼠标移动都要重绘，留在 JS 的 Canvas 2D 里更直接；WASM 只在"需要游戏真相"的地方出场：素材、校验、试玩。
- **颜色**：`theme.Tokens` 里的 `tcell.Color` 可以用 `.RGB()` 取分量。WASM 一侧用真彩色主题，不走 `Degrade`。

### 3. 关卡模型：前端用结构化文档，存盘时序列化成现有格式

前端内存里的关卡是 `{meta, width, tiles: Uint8Array(15×W), contents: Map<"x,y", {...}>, entities: [...], spawn, flag}`，不直接操作 15 个字符串，这样撤销、选区、图章都好写。序列化成文件格式的工作交给 Go（WASM 里的 `level.Format`），前后端只有一个格式化实现。

**稳定排版 `level.Format`**：字段顺序固定；`rows` 每行一个字符串；`contents` 和 `entities` 按 (x, y) 排序，每项占一行；两空格缩进，末尾换行。仓库测试对每个内置关卡断言 `Format(Parse(file)) == file`。1-1 迁移时也按这个格式重写一次。

### 4. 撤销：命令 + 差量补丁

每个编辑操作产生一个补丁 `{cells: [(i, before, after)], contents: [...], entities: [...], meta: ...}`。拖动绘制在 `pointerdown` 到 `pointerup` 之间合并成一个补丁，正好满足"一次拖动算一步"。补丁存的是差量，不是整关快照，200 步在宽 300 的关卡上也只占几百 KB。

**为什么不用快照**：实现最简单，但每步复制整关，配合草稿持久化会让 localStorage 很快写满。

### 5. 设计检查：`level.Lint`，跳跃能力从物理参数推出来

`Lint(l *Level, t *game.Tuning) []Issue` 放在一个新包 `pkg/level/lint`，因为它依赖 `game` 的参数，不能让 `level` 包反向依赖 `game`。`Issue{Severity, X, Y, Code, Message}`。错误级的问题直接由 `Parse` 的错误转换而来；为了能一次报出多个错误并带上坐标，`Parse` 内部要改成收集式，对外的 `Parse` 签名保持不变，仍返回第一个错误。

可达性用格子级搜索：

1. 先离线模拟，从 `Tuning` 求出一张"跳跃包络表"：在各种起跳速度和按跳时长下，算出（水平位移，高度差）是否可达。真正跑 `game.Player` 的物理，而不是套解析公式，这样调参之后结论自动跟着变。包络表按 `Tuning` 缓存。
2. 在"可站立格子"组成的图上，用包络表加边，从出生点做 BFS。旗杆所在列不可达 → 提示"无法到达旗杆"；在某个坑前 BFS 断开 → 提示"坑可能跳不过去"，坐标指向坑。
3. 敌人和道具不进可达性计算（敌人会动、可以踩），只做静态检查（是否在实心格里、是否悬空）。

这些都是**提示**，不阻止保存：设计者可能就想做一个要用空中二段跳的隐藏路线。

### 6. 试玩的输入与时间

浏览器有真实的 keyup，前端维护一个按键位掩码，每帧连同 `requestAnimationFrame` 的时间一起交给 WASM。WASM 内部按 60Hz 固定步长累加，和终端版一样把模拟和帧率解耦。终端版的松键超时 `releaseWindow` 只属于 `pkg/app`，试玩不经过它。这一点规格已经明确写了。

"从这里开始"：在 WASM 里构造 `World` 之后，把出生点改到目标列最高的可站立格，相机强制对准。不改关卡数据本身。

"无敌" / "大马里奥开始"：在 `game` 里新增仅供试玩使用的 `PlaytestOptions`。终端游戏永远传零值，不暴露给玩家。

轨迹：每帧记一次玩家脚底坐标、是否着地、是否刚起跳；最多保留 60 秒，也就是 3600 个点。

### 7. 元信息与格式扩展

`file` 结构新增 `meta: {title, author, description, difficulty}`，整体可选。`Level` 上对应加字段。长度上限：标题 32、作者 24、简介 140 字符，按 rune 计。新文件会带上 `meta`；`meta` 为空的旧文件不受影响。

### 8. 外观：主题预设 + 单项覆盖，按关卡覆盖颜色令牌

关卡文件新增可选的 `style`：

```json
"style": {
  "theme": "snow",
  "sky":   {"top": "#1b2a4a", "bottom": "#f3a65a"},
  "turf":  "#e8eef5",
  "brick": "blue",
  "stair": null,
  "pipe":  "#3a7bd5"
}
```

- 每一项可以写色板名（`"blue"`），也可以写 `#rrggbb`；`sky` 可以是单色字符串，也可以是 `{top, bottom}`。未写的项沿用主题，没写主题就用当前默认外观。所以没有 `style` 的关卡逐像素不变。
- **解析**：新增 `theme.LevelStyle` 和 `theme.Apply(base Tokens, Cast, style) (Tokens, Cast)`。它从基础令牌出发，只覆盖画面相关的令牌：`Sky`、`Ground`、`GroundEdge`、`GroundDeep`、`Grass`、`GrassDark`、`Brick*`、`Stone*`、`Pipe*`、`Cloud*`。HUD、菜单、角色令牌都不碰，满足"只影响本关画面"。
- **配套色自动推出**：设计者只选一种主色，高光、阴影、砖缝、土层在 OKLCH 空间里按固定明度偏移算出来，这样不同色相明暗一致。`go-colorful` 已经在依赖里（tcell 间接引入），不需要新依赖。
- **8 套主题**写成 Go 表：每套给出完整的主色，外加推荐的天空渐变。编辑器的主题卡片缩略图由 WASM 现场渲染一小段示例地形，不用另外做图。
- **天空渐变**：`Tokens.Sky` 保留为"地平线色"，供不支持渐变的代码路径使用。`render` 在清屏时按像素行在 `top` 和 `bottom` 之间插值。真彩色下逐行插值；256 色下先插值再映射色号，自然形成色带，相邻行映射到同一色号就合并。
- **云的可见性**：按天空亮度在两套云色之间选，亮天空用浅灰加深一点的底，暗天空沿用现在的白云。
- **降级与对比**：`Degrade` 对覆盖后的令牌照常工作。另加一步：前景主色与天空映射到同一个 256 色号时，沿亮度方向挪到最近的不同色号。对比提示用 CIEDE2000 色差，阈值 12，低于它就提示，只针对砖块、问号块、金币、敌人、玩家和水管的主色，与天空顶、中、底三处比较取最差值。
  - **为什么不用 WCAG 对比度**（实现时改的）：WCAG 只比亮度。金币（#f5c842）放在淡蓝天空（#a8d8ff）上，亮度几乎一样，WCAG 对比度只有 1.05，但色相差得很远，实际一眼就能看清（CIEDE2000 为 49）。用 WCAG 会把所有浅色白天天空都误报。CIEDE2000 同时考虑亮度和色相，能区分"金币配淡蓝天空"（清楚）和"金币配金黄天空"（看不清，色差约 3）。
  - 内置主题和天空预设都必须通过这项检查，有测试守着。实现时据此调整了两套主题：沙漠的天空从全金黄改为淡蓝到暖沙的渐变（原来会把金币和问号块藏起来），熔岩的砖块从暗红改为灰紫色的冷却岩石（原来会融进发红的天空）。

**为什么不让设计者逐个令牌配色**：令牌有三十多个，大部分是阴影、高光这类配套色，暴露出来会让"选颜色"变成调色板工程，也很容易配出不协调的组合。一种主色自动推出配套色，是"颜色丰富"和"好用"之间的折中。

### 9. 随机内容物：每条命开始时按种子派生

`contents` 每项新增可选的 `pool`：

```json
{"x": 21, "y": 9, "kind": "random", "pool": [{"kind": "mushroom", "w": 3}, {"kind": "oneup", "w": 1}]}
```

- `kind: "random"` 时必须有 `pool`，并且权重之和大于 0；其他 `kind` 时不能有 `pool`。都由 `Parse` 校验。
- **抽取时机**：在 `World.Reset`（开局和每次重生都会走这里）里，对每个随机方块抽一次，结果写进运行时的 `Content.Kind`；`Level.Restore` 先恢复 `random` 原值，再抽。顶击逻辑 `dispense` 完全不用改，看到的永远是已经抽好的具体内容。
- **派生**：`h = splitmix64(seed ^ life*0x9E37… ^ x<<20 ^ y)`，`h % 总权重` 落在哪一项就是哪一项。只依赖种子、命数和坐标，不共享一个顺序消费的 RNG，所以新增或删除别的方块不会影响已有方块，规格里"不受其他方块影响"由此保证。
- **种子**：`World` 新增 `Seed`。终端游戏开局用时钟生成，测试和试玩可以指定。和现有"给定相同种子可复现"的规格一致。
- **与 1-1 规格的关系**：`add-world-1-1-terminal-game` 的 blocks-and-items 要求内容物"在关卡数据中预先确定，不在顶击时随机"。本设计的随机块由关卡数据里的候选池决定，在命开始时确定，顶击时不随机，字面和意图都不冲突，所以不改那份规格。
- **试玩**：`playtest.start` 接受 `seed`；"显示随机结果"打开时，`render` 在未顶过的随机方块上叠画抽中内容的小图标，这个开关只存在于试玩。

### 10. 一键铺地面

纯前端操作，生成一个补丁：对目标列范围内最下面 N 行写入 `X`。"保留坑"开启时，跳过原本最底行不是 `X` 的列。草皮不是单独的瓦片，`render` 本来就在最上层地面画草皮，所以不需要额外处理。补丁照常进撤销栈。

### 11. 关卡目录只留一份

内置关卡唯一的家是 `pkg/level/data/`。`levels/` 目录删除；`tools/genlevel.py` 和 `make gen-level` 改为直接写 `pkg/level/data/1-1.json`，再用 `level.Format` 规整一遍（新增 `go run ./cmd/super-mario fmt-levels`）。

**两个关卡目录**（实现后按用户反馈调整，取代了原来的"导出模式"）：

- **内置目录**：在仓库里运行（从当前目录或程序所在目录往上能找到模块名为 `super-mario` 的 `go.mod`）时是磁盘上的 `pkg/level/data/`，否则是编进程序的那一份（只读）。
- **本地目录**：程序旁的 `levels/`，运行时读取，不用重新编译。拷给别人时连同这个文件夹一起拷。

两处都由新包 `pkg/catalog` 统一列出和读写，游戏选关和编辑器共用。关卡由（来源，标识）确定，同名的内置和本地关卡并列。保存写回打开时的目录；新建的关卡在仓库里存内置目录，否则存本地目录；只读的内置关卡存到本地目录。原来"不在仓库里就改成浏览器下载"的导出模式删除：用户实际用的时候没注意到下载提示，以为没保存。

### 12. 选关

`pkg/app/title.go` 的主菜单新增一个页面 `pageLevels`，复用现有的 `pauseMenu` 列表样式。数据来自 `level.EmbeddedNames()` 加上读每个关卡的 `meta`。`Options` 里记下"从哪里进的关卡"，结算之后据此决定回主菜单还是回选关列表。每关最高分从 `save.Board` 里按 `Level` 筛出来。

### 14. 编辑器界面语言

前端所有文字走一张中英文字符串表（`i18n.js`），静态 HTML 用 `data-i18n` 属性标出，切换时重建面板。来自 Go 的文字也要双语：加载错误 `level.Problem` 和设计提示 `lint.Issue` 同时带英文和中文消息，主题和色板带英文名，服务端错误返回代码由前端翻译。语言存在 localStorage，首次按 `navigator.language`。终端游戏本身仍是中文，不在这次范围内。

### 15. 从标题页启动编辑器

主菜单"设计关卡"在同一进程里起编辑器服务（随机端口），打开浏览器后回到标题页，并在标题页显示地址。服务随游戏退出而关闭；再次选择只重新打开浏览器。程序没有编进 WebAssembly 模块时，标题页提示用 `make build` 重新编译。

## Risks / Trade-offs

- [WASM 体积 3–5 MB，首次加载慢] → 走本地服务，不存在网络问题；加载时显示进度。必要时用 `-ldflags="-s -w"` 减小体积。不引入 TinyGo，避免和标准 Go 行为不一致。
- [`render` 依赖 tcell，WASM 会把 tcell 一起编进去] → 已验证能编过；体积代价可以接受。如果以后 tcell 在 js/wasm 下编不过，再把 `theme` 的颜色类型抽成自有的 RGB 类型（只是机械替换）。
- [可达性提示可能误报（二段跳、踩敌借力、龟壳）] → 只作为提示，不阻止保存；文案写"可能"；包络表默认按开启二段跳计算，和游戏默认一致。
- [解析器改成收集式时，改变了错误信息] → 对外的 `Parse` 仍返回第一条错误，已有的 `level_test` 原样要通过。
- [本地服务写仓库文件的安全面] → 只绑回环地址，校验同源，文件名白名单，只能写关卡目录，原子写入；有专门的测试覆盖路径穿越和跨源请求。
- [带 `meta` 的新关卡在旧版本游戏里加载失败] → 有意为之：关卡跟仓库同版本发布，不支持旧二进制读新关卡。
- [256 色下渐变天空出现明显色带] → 这是降级下预期的样子；色带至少保证由深到浅单调变化，不会出现颜色跳回的情况。真彩色是推荐配置。
- [自定义颜色配出可读性差的关卡] → 对比提示会提醒；主题和色板都预先检查过对比度；官方关卡评审时以提示列表为依据。
- [随机内容物让通关难度不稳定] → 只在设计者明确选了随机时才发生；设计检查不对随机块做"必须给蘑菇"之类的假设；试玩可以固定种子复现问题。
- [浏览器之间键盘事件不一致（如 Firefox 的 `/` 快速查找）] → 编辑器获得焦点时对已绑定的快捷键 `preventDefault`。

## Migration Plan

1. 先加 `level.Format` 和 `meta`，把 1-1 用新格式重写一次。这一步纯数据，游戏行为不变。
2. 合并两个关卡目录，改 `gen-level`。
3. 然后依次加入 lint、WASM、编辑器服务、前端、选关。每一步都能单独合入、单独回滚。编辑器没合入之前，游戏完全不受影响。

# Proposal

## Why

游戏目前只有 1-1 一关，后续关卡要靠大家一起出主意、一起做。但现在做一关的门槛太高：要么改 `tools/genlevel.py` 的排版脚本，要么手敲 15 行、每行两百多个字符的 JSON，对齐错一个字就整关报错；改完还要回终端里跑一遍才知道好不好玩。会设计关卡的人，不一定愿意（也不该需要）读 Go 和 Python。

所以要一个**真正好用**的关卡设计器：打开就能画，画完立刻能玩，玩完一键回来接着改，存下来的文件直接就是游戏能读的关卡数据，提个 PR 就能收进游戏。现在只有一关、数据格式还小，正是把"关卡生产线"定下来的时候；等关卡多了再补工具，每一关都要返工。

## What Changes

**新增一个浏览器里的关卡设计器，加上让社区关卡能进游戏的整条通路。**

- **设计器（网页）**：`super-mario edit` 在本机起一个只监听 localhost 的小服务，打开浏览器进入设计器。不用装任何东西，和游戏是同一个二进制。
  - 画布用游戏本身的素材画，看到的瓦片、敌人、问号块和游戏里一样。
  - 工具：画笔、矩形填充、橡皮、吸管、框选（复制 / 剪切 / 粘贴 / 拖动）；常用结构做成"图章"（任意高度的水管、阶梯、坑、一排砖、金币阵）。
  - 右键擦除、滚轮平移、Ctrl+滚轮缩放、小地图跳转、坐标与网格显示、完整撤销 / 重做、全键盘快捷键。
  - 点一下问号块就在属性面板里设内容物（6 种）、次数、是否隐藏；出生点和旗杆拖动摆放。
  - 关卡宽度可调，高度固定 15 行（和引擎一致）。
- **关卡外观（颜色尽量丰富）**：
  - **整关主题一键套用**：内置 8 套成套配色（草原、黄昏、夜晚、黎明、雪原、沙漠、地下、熔岩），点一下整关换装，套用后仍可单项微调。
  - **天空**：预设（白天蓝、黄昏橙、夜空、黎明粉、阴天灰、星空）或拾色器自定义，支持上下两色渐变。
  - **单项配色**：地面与草皮（草地绿、秋草橙、雪地白、沙漠黄、紫晶）、砖块（红砖、蓝砖、石砖、金砖）、硬块、水管（绿、蓝、橙、灰）各自可选，土层等配套色自动搭配。
  - 配色写进关卡文件，游戏里按关卡显示；终端只有 256 色或单色时自动降级为最接近的颜色。不写配色的旧关卡外观不变。
- **一键铺地面**：一个按钮把整关（或选区内）的底部铺满地面，可设厚度（1–4 层），可选择保留已有的坑；草皮按主题自动铺在最上层。
- **问号块内容物：指定或随机**：每个问号块、隐藏块可选"指定"（6 种内容物之一）或"随机"。随机时勾选候选内容并设权重（默认等权），属性面板实时显示各项概率。随机块在每条命开始时用种子抽一次，这条命里不变；同一种子下结果完全可复现。
- **即时试玩**：按一个键，就在设计器里用**游戏本体的物理和渲染**（编译成 WASM）开始玩，可以从起点开始，也可以从鼠标所在的列开始；随机块可固定种子或一键换种子重抽；死亡或按 Esc 立刻回到编辑，视图停在原处。试玩时记下走过的轨迹，回到编辑后叠加显示。
- **设计检查**：边画边检查。**错误**（不能保存成正式关卡）：游戏加载时会拒绝的任何问题，复用同一套 Go 校验代码，绝不两套规则。**提示**（可以保存）：旗杆可能够不着、坑太宽跳不过、出生点附近有敌人、问号块被封死顶不到等。点一条检查结果，画布就跳到出问题的格子。
- **保存与草稿**：直接存进仓库的关卡目录，不走浏览器下载；未保存的改动自动存草稿，关掉页面再打开还在。也能打开现有关卡（包括 1-1）在它的基础上改。
- **关卡元信息**：关卡文件新增可选的标题、作者、简介、难度字段，给选关界面和贡献记录用。
- **选关**：标题页新增"选择关卡"，列出所有内置关卡（显示标题、作者、难度），选中即开始。不做连续闯关。
- **贡献通路**：新增贡献指南（怎么画、怎么试、命名规则、提 PR 前要过的检查）；`go test` 自动校验仓库里的每一个关卡，CI 上不合格的关卡进不来。
- **关卡目录统一**：内置关卡只保留一份，放在 `pkg/level/data/`，去掉 `levels/` 与它之间的手工拷贝。**BREAKING**（只影响开发者）：`make gen-level` 改为直接写入 `pkg/level/data/`。

**明确不做（本变更范围外）**

- 新的关卡元素（移动平台、地下主题、水管进子关卡、新敌人等），设计器只能放引擎已支持的元素
- 关卡之间的连续闯关、世界地图
- 在线分享、关卡上传服务器、评分
- 终端内的编辑器
- 多人同时编辑同一关卡

## Capabilities

### New Capabilities

- `level-editor`：浏览器里的关卡编辑体验：启动方式、画布与素材、编辑工具与图章、属性面板、撤销重做、快捷键、草稿与保存。
- `level-playtest`：设计器内的即时试玩：用游戏本体的物理与渲染运行当前关卡、选择起点、回到编辑、轨迹回放。
- `level-contribution`：关卡元信息、设计检查（错误与提示两级）、仓库内关卡的自动校验、命名规则与贡献指南。
- `level-appearance`：关卡外观：整关主题预设、天空纯色与渐变、地面草皮砖块硬块水管的单项配色，配色在关卡文件中的表达，以及终端色彩能力下的降级。
- `random-block-content`：问号块与隐藏块的随机内容物：候选池与权重、每条命开始时按种子抽取、可复现性。
- `level-select`：标题页的选关：列出内置关卡及其元信息，选中后开始游戏。

### Modified Capabilities

（无。关卡数据格式的现有要求定义在尚未归档的 `add-world-1-1-terminal-game` 变更里，主规格目录还是空的。本变更只在格式上**新增**可选字段，旧关卡文件照常加载，相关新增要求写在 `level-contribution` 中。）

## Impact

- **新增代码**：`pkg/editor`（本地 HTTP 服务、读写关卡、内嵌网页资源）；`web/editor/`（设计器前端，原生 HTML/JS，不引入构建工具链）；`cmd/wasm`（把关卡校验、检查、试玩编译成 WASM 的入口）。
- **改动代码**：`pkg/level`（元信息、`style` 配色、随机内容物字段，可复用的设计检查）；`pkg/game`（每条命开始时抽取随机内容物）；`pkg/render` 与 `pkg/render/theme`（按关卡覆盖配色、天空渐变）；`pkg/app/title.go`（选关页）；`cmd/super-mario/main.go`（`edit` 子命令）；`Makefile`（构建 WASM、`gen-level` 改目标）；`tools/genlevel.py`（输出路径）。
- **渲染依赖**：`pkg/render/theme` 用 `tcell.Color` 做颜色令牌。WASM 里要把令牌换成 RGB，这个转换要和终端用的那份对得上。
- **依赖**：不新增第三方 Go 依赖；前端只用浏览器原生能力。
- **文档**：README 新增"设计关卡"一节；新增 `CONTRIBUTING-LEVELS.md`。
- **兼容性**：旧关卡文件不受影响。带新元信息字段的关卡文件，旧版本游戏会拒绝加载（解析器拒绝未知字段），这是有意为之。

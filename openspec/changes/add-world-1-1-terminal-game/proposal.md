# Proposal

## Why

`D:\jarvis\link_chat` 已经证明了一件事：在终端里做一整套有质感的界面是可行的——语义化色彩令牌、固定间距网格、克制的分隔线、只在必要处出现的强调色。但那套语言是给"信息型"界面用的：列表、正文、输入框。

超级马里奥要的是另一种东西：一个有物理、有节奏、有反馈的实时动作游戏。终端没有图形 API，只有等宽字符网格和若干颜色。我们要验证的是：用同一套终端设计语言，能不能把街机时代的关卡手感做出来——加速、摩擦、可变跳跃高度、踩敌人的时机窗口、顶砖块的顿挫感。

第一关（World 1-1）是最好的试金石。它是整个系列的教科书：单一的从简到繁的教学曲线，没有一行冗余设计。把它做扎实，后面每一关才有可复用的底子。

**为什么是现在**：工程目前是空的，还没有历史包袱。先把引擎骨架、关卡管线、渲染管线一次定对，比后期在 20 个关卡的代码里返工便宜得多。

## What Changes

**新建一个单机、离线的终端马里奥游戏，第一关做到完整还原。**

- **游戏引擎**：固定步长（1/60 s）的确定性主循环，状态机管理标题、游戏中、暂停、死亡、过关、结算；与渲染帧率解耦。
- **玩家物理**：走跑两级速度、加速与摩擦、滑铲转向、可变跳跃高度（按键时长）、空中惯性保留、跑动跳更远。数值对齐原版 SMB 的手感区间，而不是随手调。
- **世界与碰撞**：瓦片关卡、逐轴分离的 AABB 碰撞、单向平台、水管实体、砖块与问号块的顶击、大马里奥撑破砖块、被挤死判定。
- **敌人**：蘑菇怪、乌龟（含龟壳：踩出壳、踢壳、壳撞击连锁）、踩踏与侧面接触的区分、屏幕外休眠以避免不必要的计算。
- **道具与方块**：问号块（金币/蘑菇/星星）、金币、蘑菇（变大）、火焰花不做；星星无敌；砖块顶击动画与连击加分。
- **第一关 1-1**：完整地形、四个水管、全部敌人与方块布局、旗杆与旗降、走向城堡的过场、时间奖励结算。
- **游戏流程**：HUD（分数、金币、世界、时间、生命）、生命损失与重生、检查点不做（1-1 原版没有）、过关结算、最高分存档。
- **终端渲染**：字符像素（半块字符）渲染管线，世界坐标 → 虚拟像素 → 终端单元；视口跟随相机；色彩令牌沿用 `link_chat` 的 `ink` 主题语义；终端能力降级（无真彩色用 256 色，无色用 ASCII 与单色）。
- **输入**：键盘映射、同时按键的可用性（跑 + 跳）、可重映射的键位表、暂停与退出。

**明确不做（本变更范围外）**

- 音效与音乐（终端无法可靠发声；后续可选项）
- 第二关及以后、地下关、水管进入子关卡
- 火焰花、多种道具形态（只做小/大/星星）
- 存档进度（只存最高分）
- 联网、排行榜、回放
- 手柄支持

## Capabilities

### New Capabilities

- `game-loop`：确定性主循环——固定步长、帧调度、暂停与时间缩放、状态机、输入采样与键位映射、随机数种子的可复现性。
- `mario-physics`：玩家运动学——加速/减速/摩擦/滑铲、可变跳跃、空中控制、速度上限、形态（小/大/无敌）对运动的影响、受伤与短暂无敌。
- `world-collision`：瓦片世界与碰撞求解——逐轴扫掠、地面/天花板/墙体判定、单向平台、顶击方块、挤压致死、相机边界。
- `enemies`：敌人行为与交互——蘑菇怪、乌龟、龟壳的移动与转向、踩踏判定、壳的踢出与连锁、与方块/边界的交互、屏幕外休眠。
- `blocks-and-items`：方块与道具——问号块、砖块、金币、蘑菇、星星的自旋、道具生成动画、方块顶击动画与连击计分。
- `level-1-1`：第一关的内容与节奏——关卡数据格式、1-1 的完整布局、水管、旗杆区、通关判定与过场。
- `game-flow`：外部可见的游戏流程——HUD、生命、倒计时与时间奖励、死亡与重生、过关结算、最高分存档。
- `terminal-renderer`：终端渲染与视觉语言——字符像素合成、调色板与语义令牌、视口与缩放、绘制顺序、终端能力降级与最小尺寸处理。

### Modified Capabilities

无。这是新工程，`openspec/specs/` 目前为空。

## Impact

**新建代码**

- 模块：`super-mario`（Go 1.26+），单二进制。
- `cmd/super-mario/`：入口，参数（`-level`、`-theme`、`-scale`）与终端初始化。
- `pkg/engine/`：主循环、固定步长时钟、状态机、输入队列。
- `pkg/game/`：游戏领域模型——玩家、敌人、方块、道具、相机、计分。
- `pkg/level/`：关卡数据格式、解析、内嵌的 1-1 关卡资源。
- `pkg/render/`：字符像素画布、调色板、精灵表、视口变换。
- `pkg/tui/`：复用 `link_chat` 的 `theme`（`ink`/`paper` 语义令牌）与 `layout`（间距网格）思路，按终端游戏的需要裁剪后重建，不直接引用其模块。
- `pkg/save/`：最高分存档（`%APPDATA%` 或用户家目录下的 JSON）。

**依赖**

- `github.com/gdamore/tcell/v2`：终端事件与渲染。
- `github.com/mattn/go-runewidth`：字符宽度，避免 CJK 界面文案与半块字符错位。
- 标准库 `math`、`encoding/json`、`time`。

**风险**

- **终端分辨率与帧率**：tcell 的差量刷新足以支撑 60 fps，但某些终端（尤其 Windows 老 conhost）在高频刷新下会掉帧。缓解：渲染与物理解耦，渲染默认 30 fps，只重绘脏区域，并提供 `-fps` 开关。
- **字符格非正方形**：终端单元宽高比约 1:2，直接映射会让画面纵向拉伸。缓解：用半块字符（`▀`/`▄`）把纵向分辨率翻倍，使虚拟像素接近正方形；降级路径下退回单字符像素并接受 1:2 的形变。
- **同时按键**：终端键盘事件的并发按键能力取决于终端与操作系统，`Shift`+方向键在部分终端被吞。缓解：键位表允许同时绑定多个键，并为"跑"提供粘滞模式（按一次锁定）。
- **手感偏差**：原版 SMB 的常量建立在 16px 瓦片、60Hz、逐帧定点数之上。缓解：以"每帧像素"为单位直接对齐原版常量，并在设计文档中记录每个数值的来源，配合可调参数表做人工校准。

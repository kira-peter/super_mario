# Spec Delta

## Purpose

定义玩家可感知的游戏流程：HUD 展示的信息、生命与倒计时的规则、死亡与重生的循环、过关结算，以及最高分的持久化。它把一局游戏从开始到结束串成完整的闭环。

## ADDED Requirements

### Requirement: HUD 信息

游戏中 MUST 常驻显示：当前分数、金币数、世界编号、剩余时间、剩余生命。HUD MUST 位于画面的固定位置，MUST NOT 随相机或关卡滚动而移动。数字 MUST 使用固定宽度对齐，MUST NOT 因数值变化而左右抖动。

#### Scenario: 数字变化不改变布局
- **WHEN** 分数从 9 增加到 10
- **THEN** HUD 的其余字段位置不变，数字区域保持固定宽度

#### Scenario: HUD 固定不滚动
- **WHEN** 相机向右推进
- **THEN** HUD 保持在同一屏幕位置，关卡内容在其下方滚动

#### Scenario: 世界编号正确
- **WHEN** 处于第一关
- **THEN** HUD 显示世界编号为 1-1

### Requirement: 分数规则

分数 MUST 只由明确定义的来源产生：踩踏敌人、踢壳、顶击方块、收集金币与道具、通关奖励、剩余时间奖励。分数 MUST 只增不减，MUST NOT 因为受伤或重试而回退。

#### Scenario: 踩踏加分
- **WHEN** 玩家踩中敌人
- **THEN** 分数立即增加，并在敌人消失位置显示得分数字

#### Scenario: 受伤不掉分
- **WHEN** 大形态玩家受伤退回小形态
- **THEN** 分数保持不变

#### Scenario: 重生后分数保留
- **WHEN** 玩家死亡并按规则重生
- **THEN** 分数与金币数保留，不回退到关卡开始时的值

### Requirement: 剩余时间与倒计时

关卡 MUST 有倒计时，初始值 MUST 明确，每秒 MUST 减少一个单位。倒计时 MUST 只在游戏中状态推进，暂停 MUST NOT 消耗时间。时间耗尽 MUST 判定玩家死亡。

#### Scenario: 正常倒计时
- **WHEN** 游戏在游戏中状态运行一秒
- **THEN** 剩余时间减少 1

#### Scenario: 时间不足时提示
- **WHEN** 剩余时间进入最后的低值区间
- **THEN** 时间显示以更高的视觉强调呈现

#### Scenario: 时间耗尽死亡
- **WHEN** 剩余时间减到 0
- **THEN** 玩家进入死亡流程

#### Scenario: 暂停不流逝时间
- **WHEN** 游戏处于暂停状态超过一秒
- **THEN** 剩余时间不变

### Requirement: 生命与重生

玩家 MUST 有初始生命数。死亡 MUST 扣除一条生命，随后 MUST 从关卡起点重新开始，MUST NOT 保留死亡时的位置或场景状态（金币、已被顶击的方块 MUST 重置）。生命耗尽 MUST 进入结算。

#### Scenario: 死亡后从起点重生
- **WHEN** 玩家死亡且仍有剩余生命
- **THEN** 关卡从起点重置，玩家回到出生点

#### Scenario: 场景状态重置
- **WHEN** 玩家在关卡中顶开过方块后死亡重生
- **THEN** 该方块重新变为未使用的状态

#### Scenario: 生命耗尽结束
- **WHEN** 玩家用尽所有生命后再次死亡
- **THEN** 游戏进入结算界面，不再重生

### Requirement: 死亡流程

死亡 MUST 有明确的动画：玩家向上弹起后落下并离开画面。死亡期间 MUST NOT 接受控制输入，MUST NOT 继续推进敌人与计时。

#### Scenario: 死亡动画播放
- **WHEN** 玩家被判定死亡
- **THEN** 玩家向上弹起并落下，动画完整播放后才进入重生或结算

#### Scenario: 死亡期间其他实体冻结
- **WHEN** 死亡动画正在播放
- **THEN** 敌人、道具与倒计时保持不动

### Requirement: 过关结算

到达旗杆并完成过场后 MUST 进入结算：将剩余时间按规则折算为分数（换算 MUST 有可见的逐步递减过程），随后显示最终分数。结算完成 MUST 允许玩家开始新的一局或退出。

#### Scenario: 时间折算为分数
- **WHEN** 玩家过关时有剩余时间
- **THEN** 剩余时间逐单位折算为分数并累加，界面上能看到数值变化的过程

#### Scenario: 结算后可重新开始
- **WHEN** 结算界面显示完毕
- **THEN** 玩家可以选择开始新的一局，分数与生命重置

#### Scenario: 中途退出保留最高分
- **WHEN** 玩家在结算前直接退出游戏
- **THEN** 本次分数若高于历史最高分，仍被写入记录

### Requirement: 最高分持久化

游戏 MUST 在本机持久化最高分。记录 MUST 在分数超过历史最高时更新，MUST 在下次启动时可读回并在标题界面显示。存档损坏或不可写时 MUST NOT 阻止游戏启动。

#### Scenario: 刷新最高分
- **WHEN** 本局分数超过之前保存的最高分
- **THEN** 最高分被更新，并在下次启动时显示为新值

#### Scenario: 存档文件损坏
- **WHEN** 最高分文件内容损坏或无法解析
- **THEN** 游戏以 0 作为最高分正常启动，不崩溃

#### Scenario: 存档目录不存在
- **WHEN** 存档所在目录不存在或不可写
- **THEN** 游戏仍可正常游玩，仅最高分无法保存，并给出一次非阻断提示

### Requirement: 标题与结算界面

标题界面 MUST 显示游戏名、世界标识、最高分与开始提示。标题与结算界面 MUST 复用游戏内的视觉语言，MUST NOT 是纯文本堆叠。

#### Scenario: 标题界面信息完整
- **WHEN** 游戏启动
- **THEN** 标题界面显示游戏名、1-1 标识、最高分与开始按键提示

#### Scenario: 按键开始游戏
- **WHEN** 玩家在标题界面按下确认键
- **THEN** 游戏进入第一关，HUD 初始化

#### Scenario: 结算界面可返回标题
- **WHEN** 玩家在结算界面按下确认键
- **THEN** 回到标题界面，最高分已刷新

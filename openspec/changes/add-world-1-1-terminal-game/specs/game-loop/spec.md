# Spec Delta

## Purpose

定义游戏的确定性主循环：固定步长的模拟时钟、运行状态机、输入采样与键位映射。所有其他能力都在这套时钟之上运行，因此它的确定性决定了整局游戏是否可复现。

## ADDED Requirements

### Requirement: 固定步长模拟

游戏模拟 MUST 以固定步长推进，步长 MUST 等于 1/60 秒。一次渲染帧内允许执行零次或多次模拟步，但 MUST NOT 出现可变步长（即模拟步的时长不随墙钟变化）。每局游戏开始时 MUST 从主循环的第 0 步开始计数。

#### Scenario: 慢机器上追赶步数
- **WHEN** 一帧的墙钟耗时超过一个模拟步长
- **THEN** 主循环在同一帧内连续执行多个模拟步，使模拟时间追上墙钟
- **AND** 每个模拟步的时长仍严格等于 1/60 秒

#### Scenario: 快机器上不加速
- **WHEN** 一帧的墙钟耗时小于一个模拟步长
- **THEN** 该帧不执行模拟步，画面保持上一状态
- **AND** 游戏速度不随显示器刷新率变化

#### Scenario: 长时间阻塞后不追平积压
- **WHEN** 单帧积压的待执行模拟步超过上限（例如终端挂起后恢复）
- **THEN** 主循环丢弃超出部分，最多执行上限数量的步
- **AND** 游戏时间向前跳进，而不是以慢动作补完所有积压步

### Requirement: 运行状态机

游戏 MUST 有明确的状态集合，至少包含：标题、游戏中、暂停、死亡、过关、结算。状态迁移 MUST 由显式事件触发。处于非游戏中状态时，模拟 MUST NOT 推进玩家、敌人与计时。

#### Scenario: 从标题进入游戏
- **WHEN** 玩家在标题界面按下开始键
- **THEN** 状态迁移为游戏中，关卡从初始位置开始

#### Scenario: 暂停冻结世界
- **WHEN** 玩家在游戏中按下暂停键
- **THEN** 状态迁移为暂停，画面保留最后一帧内容
- **AND** 时间、敌人与物理全部停止推进

#### Scenario: 从暂停恢复
- **WHEN** 玩家在暂停状态再次按下暂停键
- **THEN** 状态回到游戏中，时钟从暂停前的步数继续，不补算暂停期间的时间

#### Scenario: 死亡期间锁定输入
- **WHEN** 玩家被判定死亡
- **THEN** 状态迁移为死亡，玩家输入不再影响任何实体运动
- **AND** 死亡动画结束后按生命规则决定重生或结算

### Requirement: 输入采样与边沿检测

输入 MUST 区分离散事件（按下、释放）与持续状态（按住）。同一模拟步内多次按下 MUST 被合并为一次。跳跃等一次性动作 MUST 使用按下边沿而非按住状态触发，且必须在下一次模拟步中被消费。

#### Scenario: 同一帧内连按两次跳跃
- **WHEN** 玩家在一个模拟步内两次收到跳跃键按下事件
- **THEN** 只有一个跳跃边沿被该步消费
- **AND** 不会因为多按一次而触发第二次跳跃

#### Scenario: 按住方向键持续移动
- **WHEN** 玩家持续按住右方向键
- **THEN** 每个模拟步都采样到方向为右，玩家持续推进加速
- **AND** 方向键的按住不产生额外的离散事件

#### Scenario: 事件与模拟步解耦
- **WHEN** 一帧内收到多个输入事件但只执行一个模拟步
- **THEN** 这些事件按到达顺序进入输入队列，在该步内全部被采样
- **AND** 下一个模拟步不会重复看到已经消费的按下事件

### Requirement: 键位映射

所有可操作动作 MUST 通过键位表间接绑定，MUST NOT 在逻辑代码中硬编码具体按键。键位表 MUST 至少覆盖：左移、右移、下蹲或进入水管、跳跃、加速跑、暂停、退出、确认。同一个动作 MUST 允许绑定多个按键。

#### Scenario: 跳跃绑定多个按键
- **WHEN** 跳跃动作同时绑定空格与字母键
- **THEN** 按其中任意一个都产生相同的跳跃边沿
- **AND** 两者同时按下不会产生两次跳跃

#### Scenario: 按键被终端吞掉时仍有替代路径
- **WHEN** 终端无法上报某个修饰键组合（例如加速跑的修饰键绑定）
- **THEN** 该动作的其余绑定仍然可用，游戏保持可玩

#### Scenario: 退出键在暂停以外的状态也生效
- **WHEN** 玩家在游戏中按下退出键
- **THEN** 游戏结束并恢复到进入终端界面之前的状态
- **AND** 退出前已完成最高分写入

### Requirement: 可复现的模拟

给定相同的初始状态、相同的输入序列与相同的随机种子，模拟 MUST 产生完全相同的结果。逻辑层 MUST NOT 读取墙钟时间作为模拟输入；所有时间相关判断 MUST 使用已执行的模拟步数。

#### Scenario: 相同输入重放出相同结果
- **WHEN** 用同一初始状态、同一种子与同一输入序列运行两次
- **THEN** 两次的玩家位置、敌人位置与得分在每个步数上完全一致

#### Scenario: 模拟不读墙钟
- **WHEN** 在加入人为延迟的环境中运行游戏
- **THEN** 玩家在固定步数后的位置与无延迟时相同
